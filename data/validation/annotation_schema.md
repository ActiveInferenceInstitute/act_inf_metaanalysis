# Rule-Based Reference-Annotator Agreement Schema

Stratified sample for extraction quality assessment (protocol 1B).

**This is NOT a human validation study.** Both "annotators" are deterministic
keyword-and-negation rule protocols (`analysis.validation_labeling.apply_primary_rule_protocol`
/ `apply_secondary_rule_protocol`), not humans. They provide an independent,
fully reproducible reference against which the LLM extraction pipeline's
triage is compared — a reproducibility floor, not an accuracy-against-gold
measurement. Human gold-standard annotation is future work (see the
manuscript conclusion, "Human spot-check coverage"). A genuine human pass can
still be merged in later: `scripts/07_run_validation_study.py --no-auto-labels`
leaves any pre-filled `ref_*` column untouched instead of overwriting it with
rule output.

## Sample

- Source: `output/validation/sample.csv` (generated by `scripts/07_run_validation_study.py`)
- Stratification: hypothesis × triage direction × year bin
- Target: ≥10% of assertions or ≥200 rows (whichever is larger, capped by available cells)

## Label file

| File | Role |
| --- | --- |
| `output/validation/labels_rule_reference.csv` | Primary rule protocol (`ref_*` columns) + secondary rule protocol (`secondary_*` columns), both deterministic keyword rules |

There is a single labeled file, not two independent files — both reference
columns are produced by rule protocols over the same input, so writing two
copies would falsely imply two independent annotators.

## CSV columns

| Column | Description |
| --- | --- |
| `assertion_id` | Stable row identifier |
| `paper_id` | Canonical paper ID (DOI / arXiv / S2 / OpenAlex) |
| `hypothesis_id` | One of the hypothesis registry IDs |
| `pipeline_triage` | Pipeline output at sample time |
| `source_claim_text` | What the paper explicitly states (layer 1) |
| `evidence_quote` | Verbatim quote supporting the claim, if any |
| `evidence_status` | `explicit_claim` \| `mentions` \| `no_evidence` |
| `evidence_type` | `theoretical` \| `empirical` \| `none` |
| `paper_title`, `paper_year`, `abstract_excerpt`, `stratum` | Sampling context |
| `ref_triage`, `ref_evidence_status`, `ref_evidence_type`, `ref_source_claim` | Primary rule protocol output |
| `secondary_triage`, `secondary_evidence_status`, `secondary_evidence_type` | Secondary rule protocol output |
| `error_type` | Error taxonomy code (see below) |

## Error taxonomy

Computed by `analysis.validation_metrics.classify_error`, comparing
`pipeline_triage` against the primary rule reference (`ref_*`):

| Code | Definition |
| --- | --- |
| `over_extraction` | Rule reference `irrelevant`, pipeline not `irrelevant` |
| `direction_inversion` | Reference and pipeline both directional (`supports`/`contradicts`) but disagree |
| `quote_mismatch` | Evidence quote not a substring of the abstract excerpt |
| `triage_mismatch` | Other triage disagreement |
| `evidence_status_error` | Evidence supply status differs from the rule reference |
| `evidence_type_error` | Evidence type differs from the rule reference |

## Metrics (injected via `variables.py`, computed by `analysis.validation_metrics`)

- `VAL_N` — sample size
- `VAL_KAPPA` — inter-rule agreement (primary vs. secondary rule protocol)
- `VAL_KAPPA_PIPELINE` — rule reference vs. pipeline direction agreement
- `VAL_PRECISION`, `VAL_RECALL`, `VAL_F1` — rule reference vs. pipeline, `supports` class
- `VAL_QUOTE_FIDELITY` — `n/a` when the sampled rows carry no verbatim evidence quotes, otherwise the measured match rate
- `VAL_ERR_*` — error taxonomy rates

Output: `output/reports/validation_metrics.json` (and `output/data/validation_metrics.json`)
